## 1. Structured Asset Domain Schema (Pydantic Specification)

Every content piece generated by the IncuBrix engine conforms to a unified, strictly typed Pydantic data model. This contract governs the asset lifecycle across five distinct statuses: `DESIGNED`, `IMPLEMENTED`, `GENERATED`, `TESTED`, and `VERIFIED`.

### 1.1. Core Pydantic Models (Design Specification)

```python
from enum import Enum
from typing import List, Optional, Dict
from pydantic import BaseModel, Field, HttpUrl

class PlatformEnum(str, Enum):
    LINKEDIN = "linkedin"
    YOUTUBE_SHORTS = "youtube_shorts"
    INSTAGRAM = "instagram"
    TWITTER = "twitter"

class AssetFormatEnum(str, Enum):
    TEXT_POST = "text_post"
    CAROUSEL = "carousel"
    SHORT_VIDEO = "short_video"
    THREAD = "thread"

class PillarEnum(str, Enum):
    WORKFLOW_EDUCATION = "workflow_education"
    HOOK_TUTORIALS = "hook_tutorials"
    ONE_TO_MANY = "one_to_many"
    CREATOR_OPERATIONS = "creator_operations"
    ATTRIBUTION_EXPERIMENTS = "attribution_experiments"

class AssetLifecycleStatus(str, Enum):
    DESIGNED = "designed"          # Schema and specifications established
    IMPLEMENTED = "implemented"    # Engine modules and rendering scripts built
    GENERATED = "generated"        # Asset copy and raw media produced
    TESTED = "tested"              # Passed automated schema, duration, and link checks
    VERIFIED = "verified"          # Audited against brand guardrails and quality rubric

class VideoScene(BaseModel):
    scene_number: int
    duration_seconds: float
    visual_cue: str = Field(..., description="Visual scene instruction or text animation cue")
    voiceover_script: str = Field(..., description="Exact spoken script for narration")
    on_screen_text: str = Field(..., description="High-contrast text burned into frame")

class CarouselSlide(BaseModel):
    slide_number: int
    headline: str
    body_text: str
    visual_layout: str = Field(..., description="Layout: title_card, comparison, bullet_list, or cta_card")
    rendered_image_path: Optional[str] = None

class ContentAsset(BaseModel):
    # 1. Identity & Origin
    asset_id: str = Field(..., description="Deterministic unique identifier: asset_XX_platform_hash")
    source_document: str = Field(..., description="Filename of source input document")
    source_segment_id: str = Field(..., description="Extracted section/paragraph identifier")
    
    # 2. Categorization & Targeting
    platform: PlatformEnum
    content_format: AssetFormatEnum
    pillar: PillarEnum
    intended_audience: str = Field(..., description="Primary vs Secondary audience segment")
    
    # 3. Core Content & Copy
    hook: str = Field(..., description="Opening line / 0-3s video hook / slide 1 title")
    caption: str = Field(..., description="Full post body copy or thread content")
    hashtags: List[str] = Field(default_factory=list)
    call_to_action: str = Field(..., description="Contextual call to action")
    
    # 4. Media Specifications (When Applicable)
    video_scenes: Optional[List[VideoScene]] = None
    carousel_slides: Optional[List[CarouselSlide]] = None
    estimated_duration_seconds: Optional[float] = None
    rendered_media_path: Optional[str] = Field(None, description="Local path to .mp4 video or .png slide deck")
    editable_source_path: Optional[str] = Field(None, description="Local path to Markdown/JSON source card")
    
    # 5. Tracking & Attribution
    destination_url: HttpUrl = Field(..., description="Verified IncuBrix destination endpoint")
    utm_parameters: Dict[str, str] = Field(..., description="utm_source, utm_medium, utm_campaign, utm_content")
    final_tracking_link: str = Field(..., description="Synthesized UTM tracking URL")
    
    # 6. Evidence & Claim Verification
    evidence_references: List[str] = Field(default_factory=list, description="IDs from evidence register e.g. EV-001")
    claim_category: str = Field("Cat 1", description="Claim classification: Cat 1, Cat 2, Cat 3, or Cat 4")
    rights_metadata: str = Field("Original procedural typography & public domain TTS audio", description="Copyright clearance")
    
    # 7. Quality Gates & Lifecycle Status
    lifecycle_status: AssetLifecycleStatus = AssetLifecycleStatus.DESIGNED
    validation_passed: bool = False
    validation_warnings: List[str] = default_factory=list
    target_metric: str = Field(..., description="Target metric: 3s Retention, Saves, CTR, Reposts")
    target_value: str = Field(..., description="Target hypothesis threshold")
```

### 1.2. Mandatory Fields for an Asset to Count as Ready
An asset cannot be classified as `VERIFIED` or included in the final publishing library unless:
1. `asset_id` is populated, non-null, and verified collision-free.
2. `hook` and `caption` are populated and comply with platform length constraints.
3. `call_to_action` is paired with an exact, verified `final_tracking_link`.
4. If `content_format == SHORT_VIDEO`:
   - `video_scenes` contains at least 3 distinct scenes.
   - Spoken word count is $\le 140$ words and duration is strictly $\le 60.0$ seconds.
   - `rendered_media_path` points to an existing, valid `.mp4` file on disk.
5. If `content_format == CAROUSEL`:
   - `carousel_slides` contains between 5 and 7 slides.
   - All slide `.png` files exist on disk at 1080x1350 resolution.
6. `validation_passed == True` with zero Category 4 claim violations.

## 2. Quality Gates & The 20-Asset Randomized Audit

To satisfy assessment quality standards, the engine includes an automated quality audit procedure that randomly selects 20 assets from the generated library and scores them across 5 objective dimensions.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        QUALITY AUDIT SCORING RUBRIC                    │
├─────┬─────────────────────────────────────┬──────────────┬─────────────┤
│ #   │ Quality Dimension                   │ Weight       │ Pass Score  │
├─────┼─────────────────────────────────────┼──────────────┼─────────────┤
│ 1   │ Platform Length & Technical Spec    │ 20 Points    │ $\ge 17/20$ │
│ 2   │ Hook Structure & First-3s Focus     │ 20 Points    │ $\ge 15/20$ │
│ 3   │ Brand Voice & Anti-Slop Compliance  │ 20 Points    │ $\ge 17/20$ │
│ 4   │ Claim Accuracy & Evidence Reference │ 20 Points    │ $\ge 20/20$ │
│ 5   │ Media Render & Link Uniqueness      │ 20 Points    │ $\ge 16/20$ │
├─────┴─────────────────────────────────────┼──────────────┼─────────────┤
│ TOTAL AUDIT SCORE (Minimum Passing Bar)   │ 100 Points   │ $\ge 85/100$│
│ Stretch Performance Target                │ 100 Points   │ $\ge 90/100$│
└───────────────────────────────────────────┴──────────────┴─────────────┘
```

### 2.1. Scoring Dimensions & Rules
1. **Platform Length Compliance (20 pts):** Automated check confirming character limits (LinkedIn $\le 3,000$, X $\le 280$) and video durations (Shorts $\le 60.0$s). A duration exceeding 60.0s receives an automatic 0/20.
2. **Hook Structure (20 pts):** Confirms opening line adheres to approved archetypes (Contrarian, Quantitative, Operational) without conversational fluff.
3. **Brand Voice & Anti-Slop (20 pts):** Automated check for banned buzzwords ("game-changer", "magic", "skyrocket"). Deducts 5 points per buzzword.
4. **Claim Accuracy (20 pts):** Checks for unverified claims, fabricated stats, or ungrounded competitor assertions. Any Category 4 violation results in an immediate 0/20 and asset rejection.
5. **Media Render & Link Uniqueness (20 pts):** Confirms that rendered `.mp4` or `.png` files exist on disk, are non-empty, and carry a unique, collision-free UTM link.

### 2.2. Sampling Methodology & Acceptance Bar
* **Sampling:** Deterministic pseudo-random selection of 20 assets (`random.Random(42).sample(assets, 20)`).
* **Passing Threshold:** The sampled batch must achieve a **mean quality score $\ge 85\%$** (the assessment standard), with $\ge 90\%$ designated as an exceptional stretch target. A 100% pass rate is strictly required on Category 4 claim checks.

## 3. Actual Video and Graphic Production Specifications

The assessment requires **completed media files**, not merely text scripts. The engine utilizes a local, zero-cost rendering architecture leveraging host `Pillow` and `imageio-ffmpeg` capabilities.

### 3.1. Short-Form Video Production (YouTube Shorts / TikTok / Reels)
* **Canvas Dimensions:** Strictly **1080 x 1920 pixels** (9:16 vertical aspect ratio).
* **Duration Target:** Strictly between **35.0 and 50.0 seconds** (Hard cut guardrail at 58.0 seconds; strictly $\le 60.0$s).
* **Video Encoding:** 30 fps, MP4 container, H.264 video codec (`libx264`), AAC audio codec (128 kbps).
* **Visual Composition:**
  * Dark-mode background cards (`#0a0e27` dark navy palette verified on IncuBrix landing page).
  * High-contrast title and kinetic subtitle text rendered using Segoe UI / Arial bold fonts.
  * Preserves top 15% and bottom 20% safe zones free of critical text to avoid native UI overlap.
* **Audio & Narration:**
  * Invokes local `gTTS` (`lang='en'`, `tld='com'`) to generate spoken audio.
  * Paced to 135–145 words per minute.
* **Compositing:**
  * Uses the verified bundled FFmpeg binary:  
    `C:\Users\Harini V\AppData\Local\Programs\Python\Python314\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe`
* **Zero-Rights-Issues Guarantee:** 100% procedural typography, geometric graphic cards, and open-source TTS narration. Zero copyrighted audio, zero unlicensed likenesses, zero unverified screenshots.

### 3.2. Carousel Slide Deck Production (LinkedIn / Instagram)
* **Canvas Dimensions:** Strictly **1080 x 1350 pixels** (4:5 portrait aspect ratio).
* **Slide Count:** 5 to 7 slides per deck.
* **Typography & Layout:**
  * Slide 1: High-impact title card with topic label and contrast border.
  * Slides 2–5: Content cards with structured points, comparisons, or frameworks.
  * Final Slide: Summary checklist with destination URL and save prompt.
  * Footer: Clear slide indicator ("Slide 2 of 6") and IncuBrix branding on every slide.
* **Export:** High-resolution individual PNG images (`asset-XX_slide_1.png` to `slide_6.png`) saved under `content/media/`.

## 4. Planned Testing & Quality Gate Procedures (Phase 3)

The following automated test suite will be implemented in Phase 3 to verify all technical criteria:

1. **`test_runtime_threshold()`:** Measures total execution time using `time.perf_counter()`; asserts generation of all assets completes in $< 30.0$ minutes.
2. **`test_video_duration_and_specs()`:** Uses FFprobe to inspect all rendered `.mp4` files; asserts duration strictly $\le 60.0$s, width=1080, height=1920.
3. **`test_carousel_dimensions()`:** Inspects all rendered `.png` slides via Pillow; asserts `img.size == (1080, 1350)`.
4. **`test_schema_validity()`:** Validates all assets against the Pydantic `ContentAsset` schema.
5. **`test_utm_uniqueness()`:** Collects all generated tracking URLs into a set; asserts `len(unique_set) == len(asset_list)`.
6. **`test_randomized_20_asset_audit()`:** Samples 20 assets pseudo-randomly; asserts overall quality score $\ge 85\%$.
